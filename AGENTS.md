# Repository instructions

## Comments and documentation

These rules apply to Go, TypeScript/React, configuration, scripts, styles, and
other maintained source files. Do not add comments that merely translate syntax.

When creating a maintained source file, add a useful file-level responsibility
header unless the file is generated, declarative and self-explanatory, or the
language convention makes such a header inappropriate. Preserve comments that
document low-power HDD behavior, protocol compatibility, security, concurrency,
data semantics, and other non-obvious project constraints.

Do not mechanically rewrite every existing file solely to increase comment
coverage. Apply the standard to new code and improve nearby comments when a file
is substantively changed.
