# 资源预算、故障隔离与验收框架

> **文档状态**：运行时基础实施中；目标设备验收尚未执行
> **整理依据**：用户历轮确认 + “未单独确认项按推荐方案生成”的授权
> **说明**：技术参数的具体默认数值需要在模块实施时验证；本文不构成现网变更指令。

## 安全优先级
P0 原始业务 (Newifi NAT/Wi-Fi、N1 sing-box/Exit Node、Alienware 现有服务/HDD 休眠) > P1 核心采集 > P2 诊断/历史回放/复杂 Widget。不能因监控增加网络转发的必要依赖。

## 分设备预算
| 节点 | 主要风险 | 架构守护 |
|---|---|---|
| Newifi D2 | SSH/iw 多次查询、Flash 写入、路由处理 | 无常驻 Agent；聚合低频只读；限时与串行执行 |
| N1 | Agent/多 Plugin Runtime 占 CPU/RSS、影响代理 | 系统级资源限制、低优先级调度、熔断 |
| Alienware | 数据库写入、历史回放、Widget 查询、HDD 唤醒 | SSD 数据、查询并发上限、分层清理、休眠保护 |

Agent 插件控制循环只有在 `plugins.enabled` 显式开启且信任密钥、grant、私有目录、制品大小、轮询周期和操作超时均显式配置时才启动。控制循环独立于指标采样循环，不主动触发 Collector。Server 端只有在 SQLite、人类与设备认证、私有制品目录和单制品上限均显式配置时才挂载持久化 Desired/Reported、制品和 Owner 路由；默认关闭。该本地链路已有测试，但未在目标设备运行验收。

Agent 批量指标队列也默认关闭。启用 `metrics_batch` 必须同时配置 HTTPS、设备 Token、绝对私有状态目录、队列快照数、队列内存字节数、单批快照数和请求体字节上限。该队列只在采样循环内发送，不增加采样频率或创建重试线程；发送失败保留 pending 批次，容量耗尽或原子状态提交失败后拒绝新样本。每次状态变化使用一个 `0600` 临时文件、文件同步、原子替换和目录同步；稳定数据状态只有一个受既有条数/字节边界约束且带校验和的文件，另有一个固定锁文件；重启会恢复同一 pending ID，并清理内部命名的崩溃临时文件。损坏、身份不匹配、越界、目录已被另一进程锁定或权限过宽均拒绝启动，不自动丢弃数据。systemd 示例为 Agent 创建 `0700` 的 `/var/lib/homelab-monitor-agent`。Server 端只有在同时显式配置 HTTPS、设备凭据、私有 SSD 存储目录、单批快照上限和请求体上限时才挂载 SQLite 批量写入路由。启用任何 SQLite 存储还必须显式配置 checkpoint 检查周期、WAL 字节阈值和单次超时；运行时使用不等待活跃 Reader/Writer 的 PASSIVE 模式，记录帧数、busy、耗时和错误，正常退出前再尝试一次。checkpoint 任务不删除数据或截断 WAL。独立保留任务要求显式原始窗口、较长凭据窗口、周期、单轮删除条数和超时，使用有界事务清理过期原始快照与孤立批次凭据；它不增加设备采样。容量运行时还要求显式配置控制库页数硬上限、指标逻辑软/硬字节和共享文件系统保留字节。每个连接安装页数上限；新批次触及硬状态时先执行一次有界过期清理和 PASSIVE checkpoint，复测仍不安全则返回 HTTP 507，Agent 保留 pending 批次并最终受既有队列上限约束。同一保留周期内继续重试时直接拒绝，不反复运行紧急维护。该保护不删除未过期数据；参数尚未在目标设备调优，WAL 截断和物理空间回收仍未实现。

告警评估默认关闭，启用时必须同时给出运行周期、单轮超时、单轮规则上限、Incident 状态总上限、两个显式持续时间以及 Unknown/Disabled 行为。规则查询在存储层按稳定游标和本轮额度分页，轮次串行执行；下一轮续接并循环回绕，单条规则失败被记录并隔离。样本只来自 Server 已接收的 Current State，不向设备发请求、不启动 Collector，也不增加任何采样频率。已有 Incident 与当前规则 Revision 不一致时保留原状态并报告错误，等待后续显式迁移能力处理。

Server 人类认证与指标查询默认关闭。启用时必须同时显式配置 HTTPS、私有 SSD 存储目录、允许的 Origin、Session TTL、登录限速键容量/次数/窗口以及历史查询范围/点数预算；任一参数缺失都会拒绝启动。当前查询只读取 Server 已接收的数据，不触发 Agent 或插件采样，也不改变设备采样频率。

插件 HTTPS 控制客户端的请求总超时取自 `plugins.operation_timeout`，与一次轮询的上下文截止时间一致；普通指标发送保留既有独立 HTTP 超时，不随插件参数变化。

## 工程测量
采集成本：单次耗时、CPU 时间、RSS、FD、返回字节、失败次数。主业务影响：WAN/LAN 延迟、吞吐、错包增长、代理连接成功率、Exit Node 连通性、现有服务 p95 响应。候选阈值只能由真实环境基线和重复测试确定，不固定写死。

## 自动降级顺序
暂停限时连接诊断/历史回放 → 降低低优先级采集 → 限制存储写入/清理 → 隔离异常插件 → 必要时停止监控 Agent；不得停用 sing-box、Tailscale、NAT、DHCP 或 Wi-Fi。

## 自动化验收矩阵
| 场景 | 验收原则 |
|---|---|
| Plugin 崩溃/OOM | Agent 自身与网络本职服务保持正常 |
| 插件升级失败 | 旧版本可恢复或安全停止插件；无无限重启 |
| Server 关机 | 不缓存/补录历史，网络与代理独立运行 |
| 新增 100 条规则（负载测试规模） | N1/Newifi 采样任务次数不变化 |
| 并发打开大量 Widget | 查询降级，不触发设备侧新任务 |
| 指标库达配额 | 分层淘汰、硬保护，系统 SSD 不被填满 |
| HDD 休眠 | 不被指标、SMART 或回放任务唤醒 |

## 性能验收策略
先非侵入式观测正常业务，建立基线；用模拟插件、伪数据和隔离测试环境验证故障处理；需要主动吞吐或压测时，另由 Owner 审批维护窗口和可回滚方案。
