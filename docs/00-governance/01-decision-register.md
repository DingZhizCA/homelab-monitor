| ADR-050 | 自助订阅 API 边界 | Owner 与 Viewer 通过 HTTPS Session 只能列出和修订自己的订阅；HTTP 请求不接受 user ID，由服务绑定当前 Principal。读取必须显式提供条数上限，写入必须通过 Origin 校验、严格 JSON 和请求体限制，并提供期望 Revision 与完整订阅字段。服务保存前复核精确告警规则存在；Handler/路由可选装配，默认关闭 | 2026-10-26 按方案 A 实施 |
| ADR-051 | 订阅 API 启动装配 | `cmd/server` 只有在存储、人类认证、告警规则校验配置均已启用，并同时显式给出订阅请求字节、全局记录、单用户记录和单意图收件人数四项正值时才装配自助订阅路由。单用户上限不得超过全局上限；四项全省略时关闭，部分配置在 HTTP 监听前失败 | 2026-10-26 按方案 A 实施 |
| ADR-052 | Web 自助精确订阅 | Alerts 页面向 Owner 与 Viewer 提供当前设备的自助订阅区。列表条数上限初始为空，只有用户明确填写正整数并点击读取后才按 `device_id` 和 `limit` 查询，避免全用户结果先截断再按设备过滤。新建/修订要求明确规则、级别、启用状态和渠道；Info 禁用 Push；Revision CAS 由已读取记录产生。页面不自动读取、不创建默认订阅、不触发评估或采集 | 2026-10-26 按方案 A 实施 |
| ADR-053 | 通知收件人扇出记录 | outbox 意图在处理时按仍启用的精确订阅和活动账户选择收件人，使处理前退订生效；无匹配收件人时可正常确认意图。每个用户记录 ID 由意图 ID 与用户 ID 确定，保存完整告警身份和明确的站内/Push 渠道。单意图全部收件人记录在一个事务中幂等提交，独立总容量不足时整批失败并保留 outbox；Push 字段只代表后续待处理选择，本阶段不调用外部服务 | 2026-10-26 按方案 A 实施 |
| ADR-054 | 通知重试与死信边界 | Handler 失败增加尝试次数并记录经过空白规范化和显式字节上限截断的最近错误；未达到显式最大次数时按显式初始值和上限执行指数退避。读取只选择到期项，使延迟中的旧项不阻塞其他就绪项。达到上限时把完整意图、次数、失败时间和错误在同一事务移入有显式总容量的死信表并删除 outbox；死信容量满则保留原 outbox 项并报告失败。仓储提供显式上限的新到旧查询、受 outbox 容量约束且重置尝试状态的原子人工重入，以及按截止时间和单批上限删除最旧死信的保留原语。确认失败不计作下游投递失败，因为幂等 Handler 已可能提交 | 2026-10-26 按方案 A 实施 |

## 未批准修改的对象
OpenWrt 网络配置、N1 sing-box、Tailscale、防火墙、生产 systemd、Alienware 服务与磁盘配置均未因本套文档而被修改。代码和文档的实际落地状态以实施路线及 Git 历史为准。

## 架构与业务的分界
架构项在本套文档明确边界、协议、模块、责任及故障策略；告警阈值、具体采样频率、保留天数、默认 Widget、PWA 细节、准确率阈值等仅列为候选值或延后决议，不视为正式定稿。

## 冲突处理与维护
架构冲突先修订本台账并新增 ADR，不能直接在代码里改变已确认约束。建议架构变更记录包含：问题、候选方案、取舍、批准人、时间、影响、回滚方式。
