# SQLite 驱动候选评估记录

> **状态**：评估已完成；2026-10-22 已确认选择 `mattn/go-sqlite3`。
> **范围**：开发工作站上的合成指标批写与范围读取，不连接任何 Homelab 设备或服务。

## 当前结果

评估工具位于独立嵌套模块 [`tools/storage-eval`](../../tools/storage-eval/README.md)，不会增加 Server 或 Agent 的运行时依赖。已在相同工作负载上比较 CGO 驱动 `github.com/mattn/go-sqlite3 v1.14.52` 与 CGo-free 驱动 `modernc.org/sqlite v1.58.0`。

2026-10-17 本机基准环境：Linux/amd64，Intel Core i7-6700HQ @ 2.60 GHz，Go 1.26.8，CGO 开启。执行命令：

```sh
cd tools/storage-eval
go test -run '^$' -bench 'BenchmarkSQLite' -benchmem -benchtime=2s -count=3
```

| 场景 | `mattn/go-sqlite3` | `modernc.org/sqlite` | 工作负载 |
|---|---:|---:|---|
| 事务批量写入 | 中位数 251,263 rows/s、1.99 ms/op；范围 250,896–263,107 rows/s | 中位数 202,819 rows/s、2.47 ms/op；范围 200,704–206,433 rows/s | 每个事务写入 500 条合成 CPU 利用率指标，WAL，NORMAL 同步 |
| 有索引的范围读取 | 中位数 0.683 ms/op（0.674–0.704）；约 32.8 KB/op | 中位数 0.856 ms/op（0.856–0.904）；约 32.7 KB/op | 从 10,000 条记录中读取连续 1,000 条 |

结果是同一开发机上每项三次运行的中位数和观测范围，不作为目标设备容量、生产吞吐或 p95 指标。两项合成工作负载中 CGO 驱动本机结果较快；这只支持继续评估，不代表生产选择。存储架构文档中的保留策略、配额、实际指标模式和部署盘仍未由本结果决定。

复测与前一日的相对结果一致，但两次都使用同一开发机与合成负载，不能替代目标设备上的驱动评估、耐久性与容量验收。

评测模块另有行为测试，分别对两种驱动验证事务成功提交、约束失败后整批回滚、相同批次 ID 重试去重、同 ID 不同摘要冲突，以及正常关闭并重新打开文件库后读取已提交数据。测试使用独立的微型 fixture 表，证明的是本机驱动基本事务与正常重开行为；它不验证生产数据模式、进程崩溃恢复、断电耐久性或实际历史数据保留策略。

另做了 ARM64 交叉编译检查：`CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go test -exec=/bin/true ./...` 编译通过；`/bin/true` 只用于让 Go 跳过执行目标架构测试二进制，因此这不是 ARM64 运行测试。CGO 候选交叉编译未能执行，因为环境中没有 `aarch64-linux-gnu-gcc`。这记录了当前开发机的工具链条件，不代表目标主机缺少工具链或 CGO 一定无法构建。

## 未完成的比较与限制

- 尚未在目标设备执行驱动，或对目标存储介质、并发读写、磁盘增长、损坏 WAL 故障和实际指标查询形态做验证。根运行模块已覆盖显式 PASSIVE checkpoint 的阈值、逐操作超时配置、结果观测、循环取消和退出前操作，但尚未完成目标负载下的参数调优及 WAL 截断/空间回收。
- 候选评测模块本身只覆盖正常关闭重开；根运行模块已用正式 schema 增加 WAL 非空时直接终止子进程并重开的本机故障测试。断电及目标 SSD/文件系统同步语义仍需验证。
- SQLite WAL 要求同机文件系统等运行条件；生产路径、数据库文件拆分及空间预算需要另行设计与验收。

## 决策结果

2026-10-22 确认采用 `mattn/go-sqlite3`，仅接入中央 Server；Agent 不增加 SQLite 或 CGO 依赖。中央 Server 已确定运行在 Alienware AMD64，当前本机两轮基准中该候选的批写与范围查询结果也更好。运行时采用 `core.db` 与 `metrics.db` 两个 WAL 文件，分别使用 `synchronous=FULL` 与 `synchronous=NORMAL`。该选择记录为 ADR-019。

驱动选定不代表容量和耐久性验收完成。本机正式 schema 的进程强杀恢复和显式 PASSIVE checkpoint 已通过自动测试；目标环境构建、断电语义、并发读写、checkpoint 参数调优、WAL 截断、磁盘增长、配额及真实查询负载仍是后续关卡。保留期限、软硬配额及设备性能参数仍由后续业务和目标环境验收决定。
